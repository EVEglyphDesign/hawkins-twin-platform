Schema v1

The VIN rich-target row, coverage math, and sample fixtures.

One JSON row per VIN, produced daily by the twin. The executive control surface consumes it as the fourth cohort tile. The outbound-booking worklist consumes a filtered projection. Rows failing compliance.clean route to the review lane instead of the booking lane.

Read the schema canon (PDF) JSON Schema (Draft 2020-12)

What's in this folder

The schema

rich-target.schema.json — Draft 2020-12. Every field carries an explicit type and, where the value has a fixed vocabulary, an enum.

The scoring formula

scoring.md — deterministic 0–100 total from margin estimate, booking urgency, and time-to-expiry. Ceilings, not multipliers.

Seven sample VINs

rich-targets.sample.json — Class 8 diesel, Class 8 MX, Class 6/7, and battery electric. Synthetic VINs. The row shape a live twin will emit.

Worklist projection

rich-targets.worklist.json — the compact per-VIN view the fourth-cohort tile actually renders.

How to rebuild and validate locally

  • Regenerate the samples: python3 scripts/build_samples.py
  • Validate every row against the schema: python3 scripts/validate.py

Both scripts are deterministic. The same VIN plus the same as_of date produce the same row id (SHA-1 truncated), so daily refreshes are idempotent.

What lives on which side

  • Public — this repository: the schema, the scoring formula, the reference build/validate scripts, and the synthetic sample fixture.
  • Private — Hawkins-owned Azure Postgres: the real rich-target worklist per rooftop, with owner.customer_id resolved against the CDK customer master. Neither the payload nor the customer names ever move to this repository.
