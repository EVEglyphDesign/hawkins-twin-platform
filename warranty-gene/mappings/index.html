Field Mappings

SIR, SmartLINQ, PACCAR Solutions, DAVIE/PRS, TCS365, PRWS.

This lane names the PACCAR-owned surfaces that feed every field in the rich-target schema, and it tags each mapping honestly. No field is invented. What is in the file

Seven authoritative surfaces

SIR, SmartLINQ Service Management, PACCAR Solutions Portal, PACCAR Prognostics, DAVIE + PRS, TCS365, and PRWS — each with its role for the Warranty GENE and a citation into the Warranty Procedure Manual v2026.7 or a public Peterbilt page.

One mapping per schema field

Surface, source-field name, provenance tag, evidence line, and notes. Twin-derived fields are labelled surface: derived so the reader knows the twin, not PACCAR, is the author.

SmartLINQ severity map

The four notification levels — Stop Now, Service Now, Service Soon, Informational — with the driver-facing dash indicators from the SmartLINQ Operators Manual, and the twin action taken at each level.

Authority ladder source table

The eight bulletin types PACCAR distinguishes — Recall, MX Component Specific, Government Agency Mandated, Retrofit, Prognostic, Campaign, Fix-as-Fail, Information Only — verbatim from the Warranty Procedure Manual §4.1 (page 57), each with the manual's own definition.

Pending walkthrough items

The short working agenda for the first SIR session with Luke: the SIR-screen field labels still uncaptured, the PACCAR Solutions API contract terms, and the service-account provisioning path.

Non-movement covenant

This mapping file names PACCAR fields for the purpose of reading them into the twin. No customer PII, no VIN histories, and no coverage payload land in this public repository. The Warranty GENE's rich-target worklist stays in Hawkins-owned Azure Postgres; only the schema, the mapping, and the synthetic sample fixture are public.
